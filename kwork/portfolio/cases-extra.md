# Дополнительные кейсы и план честного демо

## Кейс 3. Сервис коротких ссылок (`url-shortener`)

**Задача.** Нужен сервис, который создаёт короткие ссылки и считает переходы, не задерживая ответ пользователю.

**Решение.** Go 1.27 + Postgres 16 + Docker Compose. Клики пишутся в фоне через каналы и воркер, батчами; при остановке сервиса очередь дописывается в БД (graceful shutdown). Покрытие тестами `internal/handler` — 88%.

**Результат.** API из четырёх эндпоинтов (создание, редирект, статистика, healthcheck), предсказуемая запись кликов, воспроизводимый запуск.

**Что доказывает.** Умею делать серверные сервисы и заботиться о том, чтобы данные не терялись на сбоях.

## Кейс 4. Прогноз оттока клиентов (`churn-analysis`)

**Задача.** Веб-сервис для прогнозирования оттока клиентов на основе машинного обучения.

**Решение.** FastAPI + три модели (Logistic Regression, XGBoost, Neural Network), сравнение по метрикам, SHAP-объяснение предсказаний, веб-интерфейс, Docker.

**Результат.** Выбрана XGBoost: accuracy 0.778, ROC-AUC 0.748; пакетный прогноз и объяснение факторов, влияющих на прогноз.

**Что доказывает.** Умею доводить модель до API и интерфейса, а не оставлять в ноутбуке.

## План честного демо-кейса по парсингу (без выдуманных цифр)

Цель: показать в портфолио реальный сбор данных, который можно проверить, не нарушая правил площадок и ToS.

**Шаг 1. Выбрать безопасный источник.** Открытый каталог или сайт, где данные доступны публично и сбор не запрещён правилами. Официальный API маркетплейса — лучший вариант, но для него нужен аккаунт продавца и ключи.

**Шаг 2. Собрать 100–300 строк.** Поля: название, цена, наличие, категория, ссылка. Ничего персонального.

**Шаг 3. Сделать два артефакта.**
- Скрипт с логом работы и понятными ошибками.
- Файл `.xlsx` с данными и вторым листом «сводка»: количество позиций, средняя цена, минимум/максимум по категории.

**Шаг 4. Снять 2–3 скриншота.** Окно запуска, файл Excel, график/сводка. Без логотипов маркетплейсов, если модерация придерётся.

**Шаг 5. Описать в формате «задача → что сделал → что получилось».** Указать объём данных и время работы — это и есть доказательство компетенции.

**Ограничение.** Если доступа к API нет, демо строится на открытом источнике и подписывается «демонстрационный пример на открытых данных» — это честно и не создаёт ложных ожиданий у клиента.
